# Back to Bucky — two-minute demo

Use the real running app and fictional records. Rehearse once; do not narrate unobserved test results or uncollected feedback. Keep API keys and staff tokens offscreen.

## 0:00–0:20 — Problem

“Back to Bucky helps students find lost belongings without publishing the private details someone could use to falsely claim them. This prototype uses eight fictional items.”

## 0:20–1:05 — Working student flow

Enter: “I lost black Sony headphones in the library.” Show a plausible public match. Supply: “Mine have a blue star sticker inside the left earcup.” Show the prepared claim and explicitly submit it. Show the pending-review receipt.

“The student supplies identifying details. A staff member makes the final decision.”

## 1:05–1:20 — Staff review

Open the staff view with its token already entered offscreen. Show the original student statements alongside the fictional staff record. Explain that the agent does not automatically approve ownership or release belongings.

## 1:20–1:45 — Art of the Break

Show one actual recorded experiment. State the precise observed baseline failure and before/after counts. If no failure was observed, say exactly that and describe the limited tests completed. Identify the baseline as an experimental version; explain that protected mode keeps private notes outside the model context.
